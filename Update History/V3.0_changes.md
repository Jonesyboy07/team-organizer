# V3.0 Changes

This file records the changes included in the V3.0 update for the Team Organizer bot.

## Storage Changes

- Moved live server configuration storage to `data/storage.db`.
- Kept `data/servers.json` as a backup and first-run migration source.
- Added first-run migration tracking through database metadata.
- Hardened server storage reads and writes against malformed rows and concurrent startup/write paths.

## Owner Command Changes

- Centralized `OWNER_ID` checks in shared utilities.
- Added `!a_help` to list owner-only commands.
- Added `!set_version <value>` to update `data/version.txt`.
- Kept slash-command syncing as an owner-triggered prefix command with `!sync_commands`.
- Kept help-document regeneration as an owner-triggered prefix command with `!refresh_help_docs`.

## Rotating Status Changes

- Added a dedicated status cog for rotating bot statuses.
- Added default rotating statuses in `data/default_statuses.json`.
- Added local custom rotating statuses in `data/custom_statuses.json`.
- Added owner commands to:
  - list statuses
  - add or re-enable statuses
  - disable statuses
  - force the next status immediately
- Added support for these status variables:
  - `{users}`
  - `{servers}`
  - `{total_teams}`
- Set status rotation to a 20-minute interval.

## Command UX and Access Changes

- Added a friendly cooldown message for `/help`.
- Kept slash-command help content generated through `data/commands.json`.
- Removed duplicated owner-ID gating logic so owner commands use one shared path.

## Setup and Documentation Changes

- Updated `prereq.py` to initialize storage and status files.
- Added `docs/storage.md`.
- Added `docs/owner-commands.md`.
- Updated `README.md` to reflect:
  - SQLite-backed storage
  - owner command setup
  - rotating status files

## Included Owner Command Flow

```text
!a_help
!set_version 2.1.0
!status_add Helping out {total_teams} teams
!status_refresh
```
