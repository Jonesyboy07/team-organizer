# V4.0 Changes

This file records the V4.0 website integration for the Team Organizer bot. The release adds a private React dashboard served by Flask and connects website requests to the running bot through a persistent SQLite queue.

## Private Dashboard

- Replaced the placeholder website page with a React/Vite dashboard served by the Flask application.
- Added a private sign-in screen, responsive desktop/mobile layouts, bot status, version, uptime, recent update text, and authorized server/team views.
- Kept server and team information behind Discord sign-in. The logged-out page does not display server counts, guild names, update messages, or personal statistics.
- Limited server views to Discord server owners/administrators and users who captain a configured team in that server.
- Restricted the tracked-user total to the bot owner configured by `OWNER_ID`.
- Added Terms of Service and Privacy Policy pages at `/terms` and `/privacy`. These are generic notices and should be reviewed for the actual hosting and legal context.
- Listed `j0nesy_` on Discord as the contact.

## Discord Sign-In and Sessions

- Added Discord OAuth sign-in using the `identify` and `guilds` scopes.
- Added a rolling 90-day server-side session so users can stay signed in while they return to the website.
- Stored only a random session identifier in the browser's HttpOnly, SameSite=Lax cookie; OAuth credentials remain server-side and are encrypted in SQLite with `WEBSITE_SECRET_KEY`.
- Renewed OAuth credentials and refreshed the user's guild membership/permission snapshot as needed.
- Added CSRF checks to logout and action-submission requests.

Website configuration uses the project's `.env` file:

- `DISCORD_OAUTH_CLIENT_ID` (falls back to `DISCORD_CLIENT_ID`)
- `DISCORD_OAUTH_CLIENT_SECRET`
- `WEBSITE_BASE_URL` (one canonical origin; the callback is derived as `/auth/discord/callback`)
- `WEBSITE_SECRET_KEY` (stable, non-empty key required for encrypted sessions across restarts)
- `WEBSITE_HOST` and `WEBSITE_PORT` (listener bind settings, not public URL settings)

## Team and Captain Workflows

- Added owner/administrator team creation with supported-game and timezone selectors, captain selection by Discord user ID, and live role/text-channel selectors.
- Added owner/administrator team settings changes and deletion.
- Added captain-accessible team preferences for scrim requests and regions.
- Preserved the bot's game assignment rule: captains can assign a game to an unassigned team; changing an assigned game requires server administration.
- Added captain/admin actions to send weekly scheduling messages and create RSVP activities in the team's configured schedule channel.
- Added a recent-actions view showing queued, running, completed, and failed operations.

## Bot Queue Integration

- Added `website_actions` in `data/storage.db` as a durable queue shared by Flask and the bot.
- Added a bot queue worker that processes requests while the bot is online, rechecks the requesting user's live guild membership and permissions, validates team/channel/role/game settings, then performs the Discord action.
- Added action status/results and logging to the existing server bot-log channel when available.
- Pending actions remain queued while the bot is offline; the dashboard polls for updated statuses and server configuration.
- Added a bot heartbeat in SQLite for online status, uptime, and server configuration selector data.

## Security and Operations

- Added security headers, private/no-store API responses, explicit JavaScript/CSS MIME types, and CSRF protection for state-changing requests.
- Added a Waitress WSGI entry point and Windows production run script; use a TLS reverse proxy for an internet-facing deployment. The regular run scripts are for local development.
- Added Vite build scripts for Windows and Linux/macOS and updated project/storage deployment documentation.
- Added regression tests for session encryption, queue lifecycle, private routes, captain/admin action authorization, and owner-only team creation.

## Setup on Another Installation

V4 must be installed alongside the bot in the same repository checkout. The bot and Flask website both use that checkout's `.env` and `data/storage.db`; do not run them from separate copies or point either process at another bot's database.

### Requirements

- Python 3.10 or newer
- Node.js 18 or newer and npm
- A Discord application and bot configured in the Discord Developer Portal
- The bot's normal required configuration, including `DISCORD_TOKEN`, `DISCORD_CLIENT_ID`, and `OWNER_ID`

### Configure and Build

1. Get the V4 project files onto the bot host and open a terminal in the repository root.
2. Create a local `.env` from the template if one does not already exist. Keep each installation's bot token, OAuth client secret, and website key private; never copy them from another operator's `.env` or commit `.env` to source control.

	```powershell
	Copy-Item .env.example .env
	```

	On Linux/macOS, use `cp .env.example .env` instead. Add the installation's own Discord bot settings and set `DISCORD_OAUTH_CLIENT_ID` (or use the existing `DISCORD_CLIENT_ID` fallback), `DISCORD_OAUTH_CLIENT_SECRET`, and a stable, randomly generated `WEBSITE_SECRET_KEY`. Generate the website key with:

	```powershell
	py -c "import secrets; print(secrets.token_urlsafe(48))"
	```

	Keep the generated key stable across restarts. Changing it invalidates existing remembered sessions and prevents decrypting stored OAuth credentials.
	On Linux/macOS, generate the key with `python3 -c 'import secrets; print(secrets.token_urlsafe(48))'`.

3. For local use, set `WEBSITE_HOST="127.0.0.1"`, `WEBSITE_PORT="9090"`, and `WEBSITE_BASE_URL="http://127.0.0.1:9090"`. Register the callback derived from this base URL in the Discord Developer Portal:

	```text
	http://127.0.0.1:9090/auth/discord/callback
	```

	If using a different local host or port, change `WEBSITE_BASE_URL` and register the matching derived callback. For a public site, set `WEBSITE_BASE_URL` to its public HTTPS origin, such as `https://dashboard.example.com`; the app builds the callback URL from that value. Use a TLS reverse proxy in front of Waitress and keep the Waitress listener private behind the proxy.

4. Install Python dependencies and build the React frontend:

	```powershell
	py -m pip install -r requirements.txt
	website\scripts\build-frontend.bat
	```

	On Linux/macOS, use `python3 -m pip install -r requirements.txt` and `sh website/scripts/build-frontend.sh`.

### Run Both Processes

Start the bot from the repository root using its normal launch command. In a second terminal, also from the repository root, start the website:

```powershell
website\scripts\run-website.bat
```

The local site opens at `http://127.0.0.1:9090`. For production on Windows, use `website\scripts\run-website-prod.bat`; on Linux/macOS use `sh website/scripts/run-website-prod.sh`. Both production commands run Waitress and should sit behind HTTPS termination at a reverse proxy. The shell launchers prefer `python3`, fall back to `python`, and honor `PYTHON` when explicitly set. The bot must be online to process queued website actions; requests remain pending while it is offline.

The first dashboard login only grants access to servers where the signed-in Discord account owns/administers the server or captains a configured team. Server team creation also requires completed bot setup in that server. Review `/terms` and `/privacy` for the operator's actual deployment and update their contact details when forking or redistributing this project.

### Example URLs

For a local installation using the default website port:

| Purpose | Example URL |
| --- | --- |
| Dashboard entry | `http://127.0.0.1:9090/` |
| Terms of Service | `http://127.0.0.1:9090/terms` |
| Privacy Policy | `http://127.0.0.1:9090/privacy` |
| Start Discord sign-in | `http://127.0.0.1:9090/auth/discord/login` |
| Discord OAuth callback | `http://127.0.0.1:9090/auth/discord/callback` |

For a public deployment, replace `dashboard.example.com` with the operator's real DNS name and use HTTPS throughout:

| Purpose | Example URL |
| --- | --- |
| Dashboard entry | `https://dashboard.example.com/` |
| Terms of Service | `https://dashboard.example.com/terms` |
| Privacy Policy | `https://dashboard.example.com/privacy` |
| Start Discord sign-in | `https://dashboard.example.com/auth/discord/login` |
| Discord OAuth callback | `https://dashboard.example.com/auth/discord/callback` |

The public callback URL must be registered exactly in the Discord Developer Portal; it is derived from `WEBSITE_BASE_URL` plus `/auth/discord/callback`. The callback is an OAuth return endpoint; users normally start at the dashboard and select **Continue with Discord** instead of opening the callback directly.

The React app calls these JSON routes after sign-in. They are not public pages: protected routes require a valid website session, and state-changing requests also require the CSRF token.

| Method and route | Purpose |
| --- | --- |
| `GET /api/session` | Check whether the browser has a valid login |
| `GET /api/dashboard` | Load private metrics and the user's authorized servers |
| `GET /api/guilds/123456789012345678` | Load teams and settings for an authorized Discord server ID |
| `GET /api/actions` | Check the signed-in user's recent queue actions |
| `POST /api/actions` | Submit a validated team, activity, or scheduling action |
| `POST /auth/logout` | End the remembered session |
